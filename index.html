Outbound Email System: Instantly + NeverBounce + QA Pipeline
Lead cleaning, email verification, suppression logic, and Instantly upload readiness
Problem

Leads were coming from different sources and needed a clean, reliable process before being uploaded into Instantly. Risks included duplicate outreach, invalid emails, and poor deliverability.

Key logic
  • Google Sheets acted as the control layer while Zoho CRM remained storage only
  • One contact per row, one email per cell, and no duplicate outreach
  • Generic emails removed before verification
  • Only VALID emails moved forward into the outbound queue
  • Master Suppression List served as the single source of truth
  • Status flow moved from Verified to Queued to Sent
Outcome

Eliminated duplicate outreach and invalid email sends before they reached inboxes. The pipeline became fully trackable from lead source to Instantly upload, with suppression logic that held across future batches.

Hiring Pipeline Automation
Intake, routing, and data sync across email, Airtable, ClickUp, and Kit
Problem

Applications landed in a shared inbox, then waited for someone to read, reply, and manually copy the data into the next tools. Response time averaged two days and tracking was inconsistent.

What I built
  • A Node.js bot that checks the hiring inbox every 5 minutes, detects new applications, and sends a personalized reply within minutes of receipt
  • Automatic Gmail thread labeling after reply so duplicate sends do not happen
  • Applicant logging to CSV plus Airtable record creation for clean intake visibility
  • A PowerShell handoff that creates ClickUp tasks and Kit subscriptions, then writes the returned IDs back to Airtable to keep the system in sync
Result

Response time dropped from two days to under five minutes. No applicant was missed or left unlogged. Data moved across the full stack automatically — no manual copy-paste, no gaps in the record.

What I watch for

Failure points I find
before they cost you

These are the points where systems fail if not structured properly.
Most automation issues are not obvious until something downstream stops working. I identify these structural gaps during builds and audits — before they affect leads, follow-up, or revenue.
🔒

Expired OAuth Tokens

The scheduler shows the task as running, but emails stop going out. No visible error. This is one of the most common points where automations quietly stop working without anyone noticing.

I document token expiry risk per integration, set up monitoring, and ensure token refresh logic is in place — or flag it as a manual renewal point before it silently breaks.

🔁

Redundant Legacy Scripts

An old automation still runs alongside the new one. Both fire, creating duplicates or conflicting records. Neither one is clearly the source of truth.

I audit what is actually running, identify overlaps, and disable or consolidate so the active system is the only one touching the data.

⚠

Silent Automation Failures

The task runs on schedule and logs show success — but the API returned an error that was swallowed. No record was created. This is the kind of gap that only shows up when someone notices missing data downstream.

I build in status flags, failed-record tracking, and logging so failures surface in the data instead of disappearing silently.

🏷

Tag Drift & Missing Tags

Tags were added when the system was built but were never cleaned up. Contacts have old tags, conflicting tags, or no tags — so segmentation and automation logic no longer triggers correctly.

I audit tag structure, standardize naming, remove stale tags, and rebuild the logic so user state is accurate and automations fire on the right people.

🔌

Disconnected APIs & Broken Triggers

A token rotated. A webhook URL changed. A field name was updated in one tool but not the other. The automation breaks and nobody knows why.

I map all integration dependencies before changes, document what breaks what, and test end-to-end after any update to confirm the system still behaves correctly.
